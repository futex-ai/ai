# Live Image API Test Protocol

## Purpose And Status

This planned protocol defines credentialed end-to-end verification for every
image-generation adapter and every image-capable exported catalog entry. The
implementation is tracked by the
[credentialed image API CI plan](../../plans/credentialed-image-api-ci.md).

The suite complements deterministic provider transport tests. It proves that
the production adapter, current model id, authentication, upstream API, and
normalized response still work together; it does not replace detailed wire
mapping tests.

## Scope

The initial provider set is Google and OpenAI because those are the providers
that currently implement `ImageGenerator`. Each provider test obtains entries
from its crate's `known_models()` and selects every entry advertising
`ModelFeature::ImageGeneration`. Adding an image model to an existing catalog
therefore adds live coverage automatically. A credential-free guard fails when
an image-capable catalog provider has no registered live-image adapter or CI
matrix entry.

The live probe covers text-to-image generation only. Image editing, reference
images, multiple outputs, masks, streaming, exact visual similarity, pricing,
storage, retention, and advanced provider controls remain covered by other
tests or outside this connectivity contract. Adding a new image provider is a
separate change, but that change must register the provider with this suite.

## Execution

`xtask/tests/live_images.rs` owns ignored provider integration tests and their
credential-free registry, workflow, runner, retry, and validation tests. Every
provider test:

1. Requires a non-empty `LIVE_IMAGE_API_KEY`; missing credentials fail rather
   than skip.
2. Loads every image-capable entry from the provider catalog and constructs the
   production adapter with `ReqwestJsonHttpClient`, explicit authentication,
   and the catalog's upstream model id.
3. Erases the concrete adapter behind `DynImageGenerator`.
4. Calls models sequentially and collects all failures for the provider before
   failing the job.
5. Retries only `RateLimited` and `TransientProvider`, with at most three total
   attempts and bounded backoff. Request, content-policy, no-image, terminal
   provider, and internal failures are not retried.

The probe request contains:

- a short, policy-safe prompt for a simple blue circle on a plain white
  background;
- no input images, selecting generation rather than editing;
- `Square` aspect;
- `Low` quality, which providers may map or deliberately ignore according to
  the image-generation protocol; and
- one output through the shared one-image boundary.

The normal workspace tests compile the ignored live cases and run every
credential-free guard without credentials or network access. The existing
`cargo xtask smoke-test` remains credential-free and does not call providers.

## Success Contract

Every successful live call must:

- report the expected normalized provider id and catalog upstream model id;
- return non-empty image bytes;
- return one of the supported `image/png`, `image/jpeg`, or `image/webp` media
  types;
- have bytes whose file signature agrees with that media type; and
- complete without persisting or printing the generated image payload.

Provider-reported usage and revised prompts are optional and are not success
requirements. The probe verifies connectivity and normalized output, not
visual quality or prompt fidelity.

## CI, Cost, And Credentials

`.github/workflows/live-images.yml` runs for same-repository pull requests
targeting `main`, on the default branch on a daily schedule, and by manual
dispatch. Forked and Dependabot pull requests do not receive credentials and
skip the credentialed jobs. The workflow must not use `pull_request_target`.

The workflow uses one matrix entry per registered image provider, limits
parallelism to one, generates exactly one low-quality image per catalog model,
and exposes only the current provider's secret to its credential check and test
steps. Generated bytes are process-local: CI must not log, upload, cache, or
retain them as artifacts.

The required repository Actions secrets are:

| Provider | Secret |
| --- | --- |
| Google | `GOOGLE_API_KEY` |
| OpenAI | `OPENAI_API_KEY` |

On an eligible event, a missing secret is a failing configuration error. Live
calls are billable, and catalog growth increases the cost by one generation per
new image-capable entry per run.

## Local Invocation

Run one provider explicitly with its billable credential:

```sh
LIVE_IMAGE_API_KEY="$OPENAI_API_KEY" cargo test --locked -p xtask \
  --test live_images openai_image_catalog -- --ignored --exact --nocapture
```

Omit `--ignored` to run only credential-free coverage and runner tests.
