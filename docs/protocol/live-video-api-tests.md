# Live Video API Test Protocol

## Purpose And Status

This protocol defines implemented credentialed end-to-end verification for
every video-generation adapter and every video-capable exported catalog entry.
The implementation is tracked by the
[video generation plan](../../plans/add-video-generation-support.md).

The suite complements deterministic provider transport tests. It verifies that
the production adapter, current model id, authentication, asynchronous provider
lifecycle, download path, and normalized response still work together. It does
not replace detailed request, polling, timeout, or error-mapping tests.

## Scope

The initial providers are Google and OpenAI because they currently implement
`VideoGenerator`. Each provider test loads `known_models()` and selects every
entry advertising `ModelFeature::VideoGeneration`, so catalog additions receive
live coverage automatically. A credential-free guard fails when any
video-capable catalog provider lacks a registered adapter or workflow entry.

The live probe covers text-to-video only. First-frame input, editing,
extensions, multiple outputs, progress, cancellation, visual fidelity, audio
quality, pricing, storage, and retention remain covered by deterministic tests
or outside this connectivity contract.

## Execution

`xtask/tests/live_videos/mod.rs` owns ignored provider integration tests and
credential-free registry, runner, validation, and workflow tests. Each provider
test:

1. Requires a non-empty `LIVE_VIDEO_API_KEY`; missing credentials fail instead
   of skipping.
2. Loads every video-capable entry from the provider catalog and constructs its
   production adapter with `ReqwestJsonHttpClient`, explicit authentication,
   and the catalog's upstream model id.
3. Erases the adapter behind `DynVideoGenerator`.
4. Calls catalog entries sequentially and aggregates all provider failures.
5. Does not automatically retry. A submission may create a billable job even
   when the client receives a transport error, so retrying could create a
   duplicate render.

The portable probe contains the short prompt `A video of the words 'Thank you'
in sparkling letters`, no input image, landscape aspect, four-second duration,
720p resolution, and exactly one output through the shared one-video boundary.

The normal workspace tests compile the ignored live cases and run every
credential-free guard without credentials or network access. `cargo xtask
smoke-test` constructs both provider adapters but sends no requests.

## Success Contract

Every successful live call must:

- report the expected normalized provider id and catalog upstream model id;
- return non-empty `video/mp4` bytes;
- contain the MP4 `ftyp` box signature at bytes four through seven;
- report four seconds, 1,280-pixel width, and 720-pixel height; and
- complete without persisting, printing, or uploading generated bytes.

Usage is not a success requirement because the current provider endpoints do
not expose normalized token usage for these jobs. The probe verifies
connectivity and normalized output, not visual or audio quality.

## CI, Cost, And Credentials

`.github/workflows/live-videos.yml` runs for same-repository pull requests
targeting `main`, on the default branch daily, and by manual dispatch. Forked
and Dependabot pull requests skip credentialed jobs. The workflow must not use
`pull_request_target`.

The provider matrix has a maximum parallelism of one and a 30-minute job
timeout. It exposes only the current provider's secret to the credential check
and test steps. Generated bytes remain process-local and must not be logged,
uploaded, cached, or retained as artifacts.

| Provider | Secret |
| --- | --- |
| Google | `GOOGLE_API_KEY` |
| OpenAI | `OPENAI_API_KEY` |

On an eligible event, a missing secret is a failing configuration error. Every
live request can be billable, and a timed-out local call may leave a provider
job running. OpenAI's video API is scheduled to shut down on September 24,
2026; the corresponding live job is expected to expose any earlier loss of
availability.

## Local Invocation

Run one provider explicitly with its billable credential:

```sh
LIVE_VIDEO_API_KEY="$OPENAI_API_KEY" cargo test --locked -p xtask \
  --test live_videos catalog_tests::openai_video_catalog \
  -- --ignored --exact --nocapture
```

Run all credential-free guards with no provider calls:

```sh
cargo test --locked -p xtask --test live_videos
```

## Extending Coverage

Adding a video-capable catalog entry to a registered provider requires no
workflow change. Adding another provider requires its `VideoGenerator`
implementation and catalog capability, provider registry mapping, ignored test,
workflow matrix entry and secret, documentation, and a passing credential-free
suite in the same change.
